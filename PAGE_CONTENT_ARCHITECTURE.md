# Page Content Architecture

**Status:** VERIFIED COMPLETE as the product decision matrix; implementation status is tracked in `INTERFACE_MIGRATION_PLAN.md`.

## Decision rules

1. كل صفحة تبدأ بسؤال تشغيلي واحد، وليس بمجموعة cards غير مرتبطة.
2. الإجراء الرئيسي يظهر في header أو في أول منطقة عمل، ويكرر داخل الصف/التفصيل فقط عند الحاجة.
3. البيانات المالية تستخدم مسمياتها الدلالية: تحصيل، إيراد، متبقي، تأمين مسترد/محتجز، مصروف.
4. الحالة والموعد والمالك/العميلة والكود تظهر قبل التفاصيل الثانوية.
5. الهاتف يعرض القرار والإجراء أولاً، ثم التفاصيل القابلة للطي أو صفحة التفصيل؛ لا نصغّر جدول desktop حتى يصبح غير مقروء.
6. كل صفحة تملك loading، empty، no-results، error، success، permission/offline treatment حسب قابلية الحالة.

## State vocabulary

- **L:** loading/skeleton أو `RouteLoadingFallback` أثناء hydrate.
- **E:** first-use empty مع سبب وزر بداية.
- **N:** no-results بعد بحث/فلتر مع clear filters.
- **F:** failure/error مع سبب عربي وretry دون فقد المدخلات.
- **S:** success/status announcement مع بقاء السياق.
- **O:** offline/local-only/persistence warning دون ادعاء المزامنة.
- **P:** permission denied/expired session.
- **D:** destructive confirmation قبل archive/delete/reset/close/cancel.

## Content intentionally not promoted

- لا نضيف revenue charts أو total cards بلا سؤال قرار.
- لا نعرض private customer history في public routes.
- لا نكرر كل تفاصيل العقد داخل dashboard؛ نعرض deadline/status ثم نفتح المصدر.
- لا نعرض internal audit tokens أو server snapshots للموظفة كبيانات تشغيل.
- لا نجعل map country-only يبدو كعنوان تفصيلي؛ النص العام يظل «سلطنة عمان» والخريطة تبقى رابطاً منفصلاً قابلاً للتعديل.
